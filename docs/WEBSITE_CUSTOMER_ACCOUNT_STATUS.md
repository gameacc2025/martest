# وضعیت صفحات حساب مشتری و استعلام‌های Website

**تاریخ:** 2026-11-04  
**دامنه:** Website / CUSTOMER  
**وضعیت:** بهبود رابط و کنترل دسترسی سمت Router؛ سرویس‌های موجود استفاده می‌شوند.

## آدرس‌های مشتری

صفحه `/profile/addresses` از endpointهای واقعی `/addresses` استفاده می‌کند. Backend این مسیرها را با `requireAccessType('CUSTOMER')` محافظت کرده و همه عملیات را به شناسه کاربر احراز هویت‌شده محدود می‌کند.

بهبودهای این مرحله:
- تبدیل ارقام فارسی و عربی شماره تماس و کد پستی به ارقام ASCII پیش از ارسال API.
- اعتبارسنجی ورودی‌های ضروری و محدودیت طول شماره تماس مطابق schema سرور.
- اعتبارسنجی کد پستی در صورت ورود؛ فقط رقم پذیرفته می‌شود.
- جلوگیری از ارسال تکراری درخواست تغییر آدرس پیش‌فرض و نمایش وضعیت عملیات.
- نمایش خطای اعتبارسنجی در فرم، بدون ارسال درخواست نامعتبر.

## پروفایل

صفحه `/profile` از context احراز هویت برای نمایش مشخصات استفاده می‌کند و عملیات پروفایل/رمز/تصویر را از auth store فراخوانی می‌کند. در این مرحله قرارداد Backend آن عملیات تغییر داده نشده است؛ پیش از توسعه بیشتر باید پیاده‌سازی دقیق store و endpointهای مربوطه با هم تطبیق داده شوند.

## مرکز استعلام مشتری

صفحه `/my-inquiries` از APIهای موجود استعلام استفاده می‌کند. اصلاحات این مرحله:
- جلوگیری از نمایش پاسخ دیررس درخواست استعلام قبلی پس از جابه‌جایی سریع بین جزئیات استعلام‌ها.
- پاک‌سازی پیام پیش‌نویس، انتخاب شرکت و وضعیت پیامک هنگام تغییر استعلام.
- حذف گزینه‌های تکراری شرکت دریافت‌کننده در صورت وجود چند پاسخ از یک شرکت.
- انتخاب خودکار شرکت در حالتی که تنها یک شرکت پاسخ‌دهنده وجود دارد.
- نمایش خطای دریافت پیام‌ها به‌جای نمایش اشتباه وضعیت «هنوز پیامی ثبت نشده» و امکان تلاش مجدد.

قواعد محرمانگی پاسخ‌ها، سهمیه پیام و SMS همچنان توسط API کنترل می‌شوند؛ UI مرجع مجوز یا سهمیه نیست.

## کنترل دسترسی مسیرها

مسیرهای پروفایل، دفترچه آدرس و استعلام‌های ارسالی در Website اکنون customer-only هستند. اگر حساب COMPANY یا STAFF مستقیماً URL این صفحات را باز کند، Router آن را از طریق PKCE به مسیر متناظر در پنل خودش هدایت می‌کند. این کنترل UX است؛ مجوز نهایی همچنان باید در Backend enforce شود.

## محدودیت بررسی

تغییرات در این مرحله روی فایل‌های Website و Router متمرکز بوده‌اند. تست Vitest، build و browser test اجرا نشده‌اند. Backend، Prisma schema و migrations تغییر نکرده‌اند.
