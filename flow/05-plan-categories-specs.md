# پلن کامل دسته‌بندی‌ها و کتابخانهٔ مشخصات فنی — پروژه Martest

**نسخه:** ۱.۰ (پیش از پیاده‌سازی)
**تاریخ تدوین:** ۱۰ مرداد ۱۴۰۵ (۱۰ اوت ۲۰۲۶)
**وضعیت:** پلن نهایی، آماده برای پیاده‌سازی مرحله‌به‌مرحله
**مبتنی بر بررسی کد فعلی ریپازیتوری:** `gameacc2025/martest` (آخرین کامیت در زمان بررسی: `1ffe32e`)

---

## ۱. هدف این سند

این سند طراحی کامل مدیریت دسته‌بندی‌ها، زیردسته‌ها، و مهم‌تر از همه **کتابخانهٔ مشخصات فنی پویا** (Specification Library) را مستند می‌کند — زیرساختی که کل سند «چرخهٔ عمر محصول» به آن وابسته است اما خودش هرگز طراحی نشده بود. این سند پنجمین سند از سری اسناد پلن پروژه است.

---

## ۲. یافته‌های کلیدی از بررسی کد فعلی

| بخش | وضعیت فعلی | نتیجه‌گیری |
|---|---|---|
| **دسته‌بندی (Category)** CRUD | توابع `createCategory`/`updateCategory`/`deleteCategory` در `category.service.js` کامل و با منطق ایمنی حذف (چک وجود محصول) نوشته شده‌اند، اما **هیچ route ای در `category.routes.js` به آن‌ها وصل نیست** (فقط چهار GET وجود دارد). | این یک باگ واقعی است، نه یک قابلیت طراحی‌نشده — فقط نیاز به اتصال route دارد. |
| فرانت ادمین (`CategoryList.vue`) | یک دکمهٔ «دسته جدید» و دیالوگ ساخت/ویرایش کامل وجود دارد که به `categoriesApi.create()` وصل است — یعنی اگر کاربر همین الان این دکمه را بزند، با خطا مواجه می‌شود چون API مقصد وجود ندارد. | تأیید مستقل بر باگ بالا. |
| **زیردسته (Subcategory)** CRUD | دقیقاً همان وضعیت دسته‌بندی — سرویس آماده، route وصل نیست. | فقط اتصال route لازم است. |
| **قالب مشخصات فنی (`SpecificationTemplate`/`SpecificationField`)** | با جست‌وجوی کامل در کل بک‌اند، **هیچ کد نوشتنی (create/update/delete) برای این دو مدل وجود ندارد** — نه سرویس، نه route، نه فرانت. تنها جایی که این مدل‌ها استفاده می‌شوند، خواندن‌شان در `category.service.js` (برای نمایش) و اعتبارسنجی‌شان در `product.service.js` (برای گیت ارسال محصول) است. | باید کاملاً از صفر طراحی و ساخته شود — این مهم‌ترین بخش این سند است. |
| **کتابخانهٔ سراسری فیلدها (`SpecificationLibraryField`)** | فقط `searchFields` و `listFields` (خواندن) پیاده‌سازی شده؛ کامپوننت `SpecificationTitleAutoComplete` در فرم محصول شرکت از همین‌ها برای پیشنهاد نام فیلد استفاده می‌کند. | نیاز به افزودن عملیات نوشتن (create/update/delete) دارد. |

## ۳. اصول کلی تصمیم‌گیری‌شده

| # | تصمیم | توضیح |
|---|---|---|
| ۱ | اتصال route های دسته‌بندی/زیردسته اولویت اول است | چون منطق سرویس از قبل آماده و تست‌پذیر است، این کار کم‌هزینه‌ترین و باارزش‌ترین قدم اول است. |
| ۲ | فقط ادمین/استف دسته‌بندی و قالب مشخصات را مدیریت می‌کنند | این بخش تاکسونومی و ساختار کل مارکت‌پلیس است؛ شرکت‌ها فقط مصرف‌کنندهٔ آن هستند (در فرم محصول). |
| ۳ | هر زیردسته دقیقاً یک قالب مشخصات فنی دارد | طبق رابطهٔ یک‌به‌یک موجود در Prisma schema (`Subcategory.specificationTemplate`)؛ این تصمیم از قبل در مدل داده وجود داشته، فقط پیاده‌سازی نشده بود. |
| ۴ | هر فیلد می‌تواند از کتابخانهٔ سراسری انتخاب شود یا کاملاً جدید باشد | فیلدهای تکراری مثل «ولتاژ» یا «نوع کانکتور» نباید در هر قالب از نو تعریف شوند؛ کتابخانه یکنواختی نام/واحد را بین دسته‌های مختلف حفظ می‌کند. اگر فیلدی کاملاً جدید تعریف شود، خودکار به کتابخانه هم اضافه می‌شود تا در آینده قابل استفادهٔ مجدد باشد. |
| ۵ | تغییر بعدی قالب، محصولات منتشرشدهٔ قبلی را قطع نمی‌کند | اگر ادمین یک فیلد جدید را به قالب اضافه/اجباری کند، محصولات منتشرشدهٔ قبلی دست‌نخورده و منتشر باقی می‌مانند. فقط یک هشدار به ادمین نشان داده می‌شود («N محصول تحت تأثیر»)؛ این هشدار مانع ذخیره نمی‌شود. محصولات جدید یا ویرایش‌شده از این پس باید طبق قالب جدید عمل کنند (همان گیت اعتبارسنجی موجود در `product.service.js`). |
| ۶ | حذف دسته‌بندی/زیردسته با محصول موجود مسدود است | این منطق از قبل در سرویس پیاده شده (`این دسته دارای محصول است. ابتدا محصولات را منتقل کنید.`)؛ فقط باید از طریق route در دسترس قرار گیرد. |

## ۴. فلوچارت ۱ — مدیریت دسته‌بندی و زیردسته

![مدیریت دسته‌بندی و زیردسته توسط ادمین](img_category_management_flow.png)

### جدول وضعیت فعلی کد (خیلی مهم برای اولویت‌بندی)

| بخش | وضعیت فعلی | کاری که لازم است |
|---|---|---|
| دسته‌بندی (Category) CRUD | منطق سرویس کامل و با ایمنی حذف آماده است؛ فقط route وصل نیست | فقط اتصال route — کار کمی دارد |
| زیردسته (Subcategory) CRUD | دقیقاً همین وضعیت | فقط اتصال route |
| قالب مشخصات فنی | هیچ کدی وجود ندارد | باید کاملاً از صفر ساخته شود |
| کتابخانهٔ سراسری فیلدها | فقط جست‌وجو/لیست (خواندن) پیاده شده | افزودن create/update/delete |
| فرانت ادمین دسته‌بندی | صفحه هست ولی دکمهٔ «دسته جدید» به API ناموجود وصل است (خطا می‌دهد) | بعد از اتصال route، خودکار درست می‌شود |
| فرانت مدیریت زیردسته/قالب | کلاً وجود ندارد | باید صفحهٔ جدید ساخته شود |

## ۵. فلوچارت ۲ — ساخت قالب مشخصات فنی برای یک زیردسته

![ساخت قالب مشخصات فنی برای یک زیردسته](img_spec_template_flow.png)

### جدول انواع فیلد پشتیبانی‌شده

| نوع | مثال |
|---|---|
| `TEXT` | نام برند سازنده (متن آزاد) |
| `NUMBER` | توان (وات) |
| `BOOLEAN` | دارای گارانتی |
| `SELECT` | نوع کانکتور (تک‌انتخابی از فهرست) |
| `MULTI_SELECT` | استانداردهای پشتیبانی‌شده (چندانتخابی) |
| `DATE` | تاریخ تولید |

هر فیلد همچنین `isRequired` (اجباری بودن در گیت ارسال محصول)، `unit` (واحد اندازه‌گیری، اختیاری)، و `sortOrder` (ترتیب نمایش در فرم) دارد.

## ۶. جدول تأثیر تغییر قالب روی محصولات موجود

| سناریو | رفتار |
|---|---|
| ادمین یک فیلد جدید به قالب اضافه/اجباری می‌کند | محصولات منتشرشدهٔ قبلی دست‌نخورده و منتشر باقی می‌مانند |
| ذخیرهٔ تغییر قالب | هشدار به ادمین: «N محصول منتشرشده تحت تأثیر این تغییرند» — فقط اطلاع‌رسانی است، جلوی ذخیره را نمی‌گیرد |
| محصولات جدید یا ویرایش‌شده پس از این تاریخ | باید فیلد جدید را طبق قالب به‌روزشده پر کنند (همان گیت اعتبارسنجی موجود در `product.service.js`) |

## ۷. جدول قطعات فنی جدید لازم

| قطعه | چرا لازم است |
|---|---|
| اتصال route های `POST/PUT/DELETE` برای Category و Subcategory | منطق سرویس آماده است، فقط باید در `category.routes.js` مسیرها اضافه شوند |
| سرویس + route کامل برای `SpecificationTemplate`/`SpecificationField` | از صفر — ایجاد/ویرایش/حذف قالب و فیلدهای هر زیردسته |
| افزودن create/update/delete به `specification-library.service.js` | فعلاً فقط خواندن دارد |
| صفحهٔ جدید مدیریت زیردسته + قالب مشخصات در `apps/admin` | کلاً وجود ندارد — باید طراحی و ساخته شود |
| منطق شمارش «محصولات تحت تأثیر» هنگام ذخیرهٔ قالب | برای نمایش هشدار غیرمسدودکننده به ادمین |
| تکمیل دکمهٔ «دسته جدید» موجود در `CategoryList.vue` | بعد از اتصال route، این بخش از فرانت خودکار کار می‌کند، فقط باید تست شود |
